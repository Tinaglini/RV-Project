# Configuração do Arquivo .env

Este documento explica como configurar o arquivo `.env` para o projeto Sistema Clientes RV.

## 📋 Passos para Configuração

### 1. Criar o arquivo .env

O arquivo `.env` já foi criado na raiz do projeto a partir do `.env.example`.

```bash
# Se precisar recriar:
cp .env.example .env
```

### 2. Configurar Variáveis de Ambiente

Edite o arquivo `.env` e configure as seguintes variáveis:

```properties
# Configurações do Banco de Dados
DB_URL=jdbc:mysql://localhost:3306/clientes_rv_db
DB_USERNAME=root
DB_PASSWORD=sua_senha_do_mysql

# Configurações JWT
JWT_SECRET=seu_secret_jwt_em_base64
JWT_EXPIRATION=86400000

# Configurações do Servidor
SERVER_PORT=8080
```

### 3. Gerar um JWT Secret Seguro

Para produção, **NUNCA use o secret padrão**. Gere um novo secret seguro:

**Opção 1 - Usando echo e base64:**
```bash
echo -n "MinhaChaveSupersecretaESegura2024ComMais32Caracteres" | base64
```

**Opção 2 - Usando OpenSSL:**
```bash
openssl rand -base64 32
```

**Opção 3 - Usando Java:**
```java
import java.util.Base64;
import java.security.SecureRandom;

SecureRandom random = new SecureRandom();
byte[] bytes = new byte[32];
random.nextBytes(bytes);
String secret = Base64.getEncoder().encodeToString(bytes);
System.out.println(secret);
```

### 4. Carregar Variáveis de Ambiente

**Em Desenvolvimento (local):**

O Spring Boot carrega automaticamente o arquivo `.env` se você usar uma biblioteca como `dotenv-java`. Mas você também pode exportar as variáveis manualmente:

```bash
# Linux/Mac
export $(cat .env | xargs)

# Windows (PowerShell)
Get-Content .env | ForEach-Object {
    $name, $value = $_.split('=')
    Set-Content env:\$name $value
}
```

**Em Produção (AWS, Docker, etc.):**

Configure as variáveis de ambiente diretamente no servidor:

**AWS Elastic Beanstalk:**
```bash
eb setenv JWT_SECRET=seu_secret_aqui JWT_EXPIRATION=86400000
```

**Docker Compose:**
```yaml
environment:
  - JWT_SECRET=${JWT_SECRET}
  - JWT_EXPIRATION=${JWT_EXPIRATION}
```

**Kubernetes:**
```yaml
apiVersion: v1
kind: Secret
metadata:
  name: app-secrets
type: Opaque
data:
  jwt-secret: c2V1X3NlY3JldF9hcXVp  # base64 encoded
```

### 5. Verificar Configuração

Inicie a aplicação e verifique os logs:

```bash
mvn spring-boot:run
```

Se o JWT_SECRET não estiver configurado, você verá um erro:
```
Could not resolve placeholder 'JWT_SECRET' in value "${JWT_SECRET}"
```

## 🔒 Segurança

### ⚠️ IMPORTANTE - Nunca commite o arquivo .env

O arquivo `.env` já está no `.gitignore` e **NÃO deve ser commitado** no repositório Git.

Verifique se está ignorado:
```bash
git status
# .env NÃO deve aparecer na lista
```

### ✅ Checklist de Segurança

- [ ] Arquivo `.env` criado
- [ ] JWT_SECRET único e seguro (mínimo 32 caracteres em base64)
- [ ] `.env` está no `.gitignore`
- [ ] `.env` NÃO está commitado no Git
- [ ] Senhas do banco de dados diferentes entre dev/prod
- [ ] Variáveis de ambiente configuradas no servidor de produção

```properties
JWT_SECRET=<GERAR_NOVO_SECRET_ÚNICO>

```

## 📝 Variáveis Disponíveis

| Variável | Descrição | Valor Padrão | Obrigatória |
|----------|-----------|--------------|-------------|
| `JWT_SECRET` | Secret para assinar tokens JWT (base64) | - | ✅ Sim |
| `JWT_EXPIRATION` | Tempo de expiração do token em ms | - | ✅ Sim |
| `DB_URL` | URL de conexão do banco MySQL | localhost:3306 | ❌ Não |
| `DB_USERNAME` | Usuário do banco de dados | root | ❌ Não |
| `DB_PASSWORD` | Senha do banco de dados | senha | ❌ Não |
| `SERVER_PORT` | Porta do servidor | 8080 | ❌ Não |

## 🆘 Troubleshooting

### Erro: "Could not resolve placeholder 'JWT_SECRET'"
**Solução:** Certifique-se de que o arquivo `.env` existe e as variáveis estão definidas.

### Erro: "Invalid JWT signature"
**Solução:** O JWT_SECRET foi alterado. Faça logout e login novamente.

### Erro: "JWT expired"
**Solução:** Token expirou. Faça login novamente para obter um novo token.
